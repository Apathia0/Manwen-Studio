# 视频镜头资产嵌入式工作流规范

## 1. 目标

本文档用于修正当前视频模式的核心交互错误：

1. 资产管理没有嵌入镜头工作流，只是独立的章节级素材仓。
2. 右侧面板没有围绕“当前镜头”组织资产，导致资产无法真正驱动视频生成。
3. 视频生成仍然偏“提示词直出”，没有形成“角色图 + 场景图 + 分镜图 + 首尾帧 -> 视频”的资产链路。

后续视频模式必须统一为：

`镜头驱动 + 右侧资产管理联动 + 资产先于视频`

---

## 2. 当前实现问题

基于当前代码，现状有三个关键错位。

### 2.1 右侧面板职责错位

当前右侧主要由 [`frontend/src/components/VideoPanel.tsx`](/C:/Users/Administrator/Desktop/Desktop/-LoreVista/frontend/src/components/VideoPanel.tsx) 承担，核心职责还是：

- 视频预览
- 提交视频任务
- 查看任务状态
- 查看片段列表

这意味着右侧是“结果面板”，不是“生产面板”。

### 2.2 资产管理是章节级，不是镜头级

当前 [`frontend/src/components/AssetManagementPanel.tsx`](/C:/Users/Administrator/Desktop/Desktop/-LoreVista/frontend/src/components/AssetManagementPanel.tsx) 的设计更像“章节资产仓库”，主要分：

- 风格预设
- 角色参考
- 场景概念
- 镜头首尾帧

问题在于：

1. 它不是围绕当前选中镜头工作的。
2. 它更像“总表浏览器”，不是“镜头资产编排器”。
3. 用户不能自然地在选中镜头后，立刻管理该镜头的角色图、场景图、分镜图和首尾帧。

### 2.3 镜头拆解和资产生成没有形成闭环

虽然当前后端已有：

- `scene_reference`
- `character_reference`
- `storyboard_frame`
- `shot_frame`

相关接口也已存在于 [`backend/routers/video.py`](/C:/Users/Administrator/Desktop/Desktop/-LoreVista/backend/routers/video.py)，但它们没有被组织成一个清晰的工作流。

现在更像：

`镜头拆解 -> 可选生成分镜图 -> 可选生成首尾帧 -> 提交视频`

正确的链路应该是：

`镜头拆解 -> AI 拆解镜头所需资产 -> 生成/选择角色图 -> 生成/选择场景图 -> 生成主分镜图 -> 生成首尾帧 -> 资产确认 -> 图生视频`

## 3. 正确的交互原则

### 3.1 当前镜头是工作流中心

视频模式下，用户选中一个镜头后，右侧面板必须切换为“当前镜头资产工作台”，而不是通用素材区。

右侧所有操作都应默认绑定当前镜头：

- 当前镜头使用的角色图
- 当前镜头使用的场景图
- 当前镜头主分镜图
- 当前镜头首帧
- 当前镜头尾帧
- 当前镜头视频生成按钮

### 3.2 资产必须有生产顺序

右侧面板不是分类收纳，而是生产步骤。

正确顺序应为：

1. 风格
2. 角色资产
3. 场景资产
4. 主分镜图
5. 首尾帧
6. 视频生成

### 3.3 视频必须消费已确认资产

视频生成不能只读 `video_prompt`。

默认输入资产必须包括：

1. 当前镜头主分镜图
2. 当前镜头首帧
3. 当前镜头尾帧
4. 当前镜头关联角色图
5. 当前镜头关联场景图
6. 当前镜头 style preset

## 4. 正确的用户流程

### 4.1 从镜头拆解进入资产工作流

在“镜头拆解”页，用户点击某个镜头卡后：

1. 中间区域显示镜头脚本和提示词。
2. 右侧区域自动切到“该镜头资产管理”。
3. 右侧顶部明确显示：
   - 镜头编号
   - 镜头标题
   - 当前风格
   - 当前资产完成度

### 4.2 AI 自动拆解镜头资产需求

当镜头生成完成后，系统应自动或半自动输出该镜头的资产需求：

- 需要哪些角色参考图
- 需要哪个场景概念图
- 需要什么主分镜图
- 是否需要首尾帧
- 是否需要上一镜头连续性引用

这一步不是让用户手工理解 prompt，而是系统给出结构化资产清单。

### 4.3 角色图管理

右侧角色资产区应展示：

- 当前镜头涉及角色列表
- 每个角色当前绑定的参考图
- 重新生成角色图
- 从历史角色图中切换主图
- 锁定当前角色图用于本镜头

这里要和漫画模式一致，强调“角色卡/角色图是可复用主资产”。

### 4.4 场景图管理

右侧场景资产区应展示：

- 当前镜头所属场次的主场景概念图
- 可选场景变体
- 将某张场景图设为当前镜头背景参考
- 重新生成当前镜头所需场景图

注意：场景资产应允许“场次级复用 + 镜头级指定”。

### 4.5 主分镜图管理

分镜图不是附属品，而是视频的主视觉锚点。

右侧应支持：

- AI 生成当前镜头主分镜图
- 展示当前主分镜图
- 查看历史变体
- 设为主图
- 审核锁定
- 局部重绘

### 4.6 首尾帧管理

在主分镜图确定后，再生成当前镜头的：

- 首帧图
- 尾帧图

首尾帧的作用：

1. 补足动作起点和终点
2. 为图生视频提供时间轴约束
3. 与上下镜头衔接

右侧应支持：

- 一键生成首尾帧
- 单独重生首帧
- 单独重生尾帧
- 设主帧
- 对比预览

### 4.7 视频生成

“生成视频”按钮必须位于资产流程的最后一步，并且默认消费：

- 主分镜图
- 首帧
- 尾帧
- 角色图
- 场景图

如果缺任一关键资产，按钮应提示缺口，不应静默降级。

## 5. 右侧面板的正确结构

右侧面板建议重构为单一组件，例如：

- `ShotAssetWorkflowPanel`

其结构不是“预览 / 资产管理”二选一，而是：

### 顶部摘要区

- 当前镜头信息
- 当前风格
- 资产完成度
- 视频状态

### Step 1 风格

- 选择当前章节或当前镜头风格 preset

### Step 2 角色资产

- 当前镜头涉及角色
- 角色图生成/切换/锁定

### Step 3 场景资产

- 当前镜头背景场景图
- 场景概念图生成/切换

### Step 4 主分镜图

- 主分镜图生成/查看/锁定

### Step 5 首尾帧

- 首帧和尾帧生成/切换/重绘

### Step 6 视频生成

- 展示将要使用的资产摘要
- 提交图生视频

### Step 7 结果预览

- 当前镜头视频
- 任务状态
- 历史片段

每个镜头卡必须展示：

- 镜头标题
- 景别
- 运镜
- 时长
- 涉及角色
- 当前主分镜图状态

- 加载该镜头的任务状态和片段

## 8. 后端工作流规范

### 8.1 镜头资产必须具备关联关系

后端需要明确支持“镜头绑定的资产集合”，而不是只允许按章节查。

建议镜头至少维护：

- `character_reference_asset_ids`
- `scene_reference_asset_ids`
- `storyboard_asset_id`
- `first_frame_asset_id`
- `last_frame_asset_id`

如果暂时不建显式字段，也要通过接口返回聚合结构。

### 8.2 镜头资产聚合接口

建议新增：

- `GET /api/shots/{shot_id}/asset-bundle`

返回结构应包含：

- 当前镜头信息
- 当前风格 preset
- 角色图资产列表
- 场景图资产列表
- 主分镜图
- 首帧列表
- 尾帧列表
- 当前用于视频生成的主资产引用

### 8.3 AI 自动拆解镜头资产需求

建议新增：

- `POST /api/shots/{shot_id}/asset-plan/generate`

返回：

- 涉及角色
- 推荐角色图
- 推荐场景图
- 主分镜图 prompt
- 首帧 prompt
- 尾帧 prompt
- 连续性来源

### 8.4 视频生成接口必须支持资产束输入

当前 `/api/shots/{shot_id}/video/render` 还偏“单个分镜图 + prompt”。

建议升级为支持：

- `source_storyboard_asset_id`
- `first_frame_asset_id`
- `last_frame_asset_id`
- `character_reference_asset_ids`
- `scene_reference_asset_ids`
- `style_preset`

这样生成视频时才是真正的“资产驱动”。

## 9. AI 自动生成逻辑要求

### 9.1 镜头拆解后自动生成的不是最终视频，而是资产计划

镜头生成完成后，AI 第一件事应该做的是：

`生成镜头资产计划`

而不是：

`生成视频`

### 9.2 资产计划输出内容

每个镜头至少输出：

- 角色需求
- 场景需求
- 分镜图 prompt
- 首帧 prompt
- 尾帧 prompt
- 视频 prompt

其中优先级顺序为：

1. 分镜图 prompt
2. 首尾帧 prompt
3. 视频 prompt

视频 prompt 不再是唯一核心。

## 11. 资产继承与复用规范

### 11.1 资产必须支持三种使用范围

每个资产都必须具备明确的使用范围，而不是默认只属于当前一次生成。

建议统一为三档：

1. `shot_only`
   - 仅当前镜头使用
2. `scene_shared`
   - 当前场次内后续镜头可继承
3. `chapter_global`
   - 当前章节全局通用，可跨场次复用

这三档适用于：

- 角色图
- 场景图
- 主分镜图
- 首尾帧
- 风格参考图

但默认建议不同：

- 角色图默认 `chapter_global`
- 场景图默认 `scene_shared`
- 主分镜图默认 `shot_only`
- 首尾帧默认 `shot_only`

### 11.2 用户必须能控制“是否继承到下镜头”

在右侧资产管理中，每个已生成资产都应有清晰操作：

- 仅本镜头使用
- 继承到下镜头
- 设为本场通用
- 设为本章通用

其中“继承到下镜头”是最重要的轻量交互。

它的意义是：

1. 当前镜头资产已满意
2. 下一镜头仍然是同一人物或同一背景
3. 用户不想重新生成相近图片浪费额度

因此系统应允许用户在当前镜头确认后，直接声明：

`该角色图 / 场景图 / 首帧 / 尾帧可作为下一镜头参考继承`

### 11.3 继承不是复制文件，而是建立引用关系

实现上不能简单复制一份图片路径，而应记录：

- 源资产 id
- 目标镜头 id
- 继承方式
- 是否强绑定

建议新增资产引用关系结构，例如：

- `source_asset_id`
- `target_shot_id`
- `inherit_scope`
- `inherit_mode`

其中 `inherit_mode` 建议支持：

- `reference_only`
  - 只作为辅助参考
- `preferred_default`
  - 下一镜头默认优先使用
- `hard_lock`
  - 下一镜头生成时必须使用

### 11.4 全局通用资产必须进入“可选资产池”

当资产被标记为：

- `scene_shared`
- `chapter_global`

它不应只停留在资产详情页，而应自动进入：

- 当前场次可选资产池
- 当前章节全局资产池

这样后续镜头生成时，用户可以直接选，不需要重复出图。

## 12. 参考漫画工作流的角色卡与垫图规范

### 12.1 角色卡必须成为视频资产的上游基础设施

视频工作流应直接复用漫画工作流中的核心思路：

`角色设定文本 -> 角色卡 -> 角色参考图 -> 后续持续复用`

也就是说，视频模式里的角色资产不能是临时图片集合，而应建立在已有角色卡之上。

建议统一分为三层：

1. `角色卡`
   - 结构化的角色外貌和气质描述
2. `角色参考图`
   - 基于角色卡生成或上传的固定角色图
3. `镜头角色引用`
   - 当前镜头实际选中的角色资产

### 12.2 全局继承逻辑应与漫画垫图一致

漫画模式中已经有成熟的：

- 故事级全局垫图
- 章节级垫图覆盖

视频模式建议对齐为：

1. `故事级全局资产`
   - 适合角色卡参考图、长期风格参考图
2. `章节级默认资产`
   - 适合本章固定服装、本章固定场景
3. `镜头级临时资产`
   - 适合当前镜头分镜图、首尾帧、局部动作参考

优先级建议固定为：

`镜头级 > 章节级 > 故事级`

这样用户上传或确认的新资产，才能像漫画模式那样自然覆盖上层默认值。

### 12.3 角色资产必须支持两种来源

视频模式中的角色资产必须允许两条入口并存：

1. 用户上传垫图
2. AI 直接生成

这两条入口都应落到同一资产体系内，而不是一条进入“上传图”，另一条进入“AI 资产”。

建议统一记录：

- `source_type`
  - `user_upload`
  - `ai_generated`
  - `ai_redraw_from_upload`
- `origin_story_asset_id`
  - 如果是从故事级资产继承而来

### 12.4 用户上传垫图不是补充功能，而是主入口之一

在很多真实项目里，用户已经有人设图、立绘、网图参考、自拍参考或团队内部设定图。

因此“上传垫图”不能藏在次级页面，必须作为角色资产和场景资产的同级入口。

右侧资产工作流中，每个资产区都应直接提供：

- 上传垫图
- AI 生成
- 基于现有图重绘

### 12.5 上传垫图后应支持 AI 标准化

用户上传的垫图质量、尺寸、背景、风格可能不统一，因此建议支持：

- 仅直接引用原图
- AI 清洗背景
- AI 重绘成统一风格
- AI 生成同角色标准参考图

也就是说，上传不是终点，上传后可以继续进入 AI 规范化流程。

### 12.6 角色卡与角色图的关系必须可见

在右侧角色资产区，应让用户清楚看到：

- 该角色来自哪张角色卡
- 当前绑定了哪张角色图
- 该角色图是上传的还是 AI 生成的
- 是否为全局默认
- 是否被当前镜头覆盖

这样产品体验才会像漫画工作流一样稳定，而不是图片越积越乱。

## 13. 手动选资产生成视频规范

### 12.1 视频生成前必须展示“已选资产清单”

点击“生成视频”前，右侧应展示本次将使用的资产包，而不是只显示按钮。

建议展示：

- 主分镜图
- 首帧
- 尾帧
- 角色参考图若干
- 场景参考图若干
- 风格 preset

### 12.2 用户必须能手动勾选参与生成的视频资产

视频生成不能只靠系统默认绑定。

用户应能在右侧资产工作流里手动决定：

- 哪张角色图参与本次视频生成
- 哪张场景图参与本次视频生成
- 是否使用主分镜图
- 是否使用首尾帧
- 是否附带上一镜头的继承资产

也就是说，最终生成视频时应该是：

`从资产池中组装一个本次生成使用的 asset bundle`

### 12.3 默认自动推荐，用户可改

推荐交互方式：

1. 系统先自动推荐一组默认资产
2. 用户可以替换其中任意一项
3. 用户点击确认后再提交视频任务

自动推荐优先级建议为：

1. 当前镜头已锁定主分镜图
2. 当前镜头主首帧/主尾帧
3. 当前镜头显式绑定角色图
4. 当前镜头显式绑定场景图
5. 上一镜头被标记为“继承到下镜头”的资产
6. 当前场次通用资产
7. 当前章节全局资产

### 12.4 资产不足时优先复用，不优先再生成

如果系统发现本镜头缺资产，优先级应改为：

1. 先推荐复用已有资产
2. 再建议用户新生成资产

例如：

- 同一角色未换装时，优先复用已有角色图
- 同一场景未切换时，优先复用场景图
- 动作变化不大时，优先复用上一镜头首尾帧做参考

这样能显著减少重复生成图片带来的资源浪费。

### 12.5 生成任务必须记录本次选用资产

后端视频任务表必须准确记录：

- 本次使用了哪些角色图
- 本次使用了哪些场景图
- 本次是否使用主分镜图
- 本次是否使用首帧/尾帧
- 本次是否带入继承资产

否则后续无法复现和优化。

## 14. 用户上传垫图与 AI 生成并存的交互规范

### 14.1 每类资产都要有双入口

以下资产都应同时支持：

1. 上传垫图
2. AI 直接生成

适用范围：

- 角色参考图
- 场景参考图
- 主分镜图
- 首尾帧

其中推荐策略不同：

- 角色图
  - 优先支持上传或从角色卡生成
- 场景图
  - 优先支持 AI 生成，也允许上传概念图
- 主分镜图
  - 优先 AI 生成，也允许上传外部分镜图
- 首尾帧
  - 优先 AI 生成，也允许上传草图或关键帧

### 14.2 上传后要立即允许设作用域

用户上传任何图片后，应立即让用户选择：

- 仅当前镜头使用
- 继承到下镜头
- 设为本场通用
- 设为本章全局
- 设为故事级默认

### 14.3 上传资产后可直接加入当前视频资产包

用户上传的图片不应先被扔进仓库再去别处挑选。

上传完成后，应该直接出现操作：

- 设为当前角色参考
- 设为当前场景参考
- 设为当前主分镜图
- 设为当前首帧
- 设为当前尾帧
- 加入本次视频生成

### 14.4 AI 生成资产也要允许回写为全局资产

AI 自动生成出来的资产，如果用户满意，也应允许一键提升为：

- 本场通用
- 本章全局
- 故事级默认

这样 AI 生成的好图就能沉淀，不需要后续重复出图。

## 15. 右侧资产管理交互补充

### 13.1 每张资产卡必须有继承控制

每张资产卡建议增加以下操作：

- 设为当前镜头使用
- 继承到下镜头
- 设为本场通用
- 设为本章通用
- 取消继承

### 13.2 资产卡必须显示当前作用域

例如在卡片上明确显示标签：

- `本镜头`
- `下一镜头继承`
- `本场通用`
- `本章通用`

这样用户才能直观看出某张资产为什么会出现在后续镜头里。

### 13.3 需要“本次视频使用资产”暂存区

在右侧面板底部建议增加一个固定区域：

- `本次视频使用资产`

里面展示已选中的：

- 角色图
- 场景图
- 主分镜图
- 首帧
- 尾帧

用户可以随时：

- 添加
- 删除
- 替换
- 恢复系统推荐

这会比“在多个分类里分散勾选”更清晰。

## 17. 后端接口补充建议

建议新增以下接口：

- `GET /api/shots/{shot_id}/asset-bundle`
  - 获取当前镜头的推荐资产包和可选资产池
- `PUT /api/video-assets/{asset_id}/scope`
  - 修改资产作用域和继承策略
- `POST /api/shots/{shot_id}/asset-bundle/select`
  - 手动选择本次视频生成使用的资产
- `POST /api/shots/{shot_id}/asset-bundle/reset`
  - 恢复系统推荐资产包
- `GET /api/shots/{shot_id}/asset-pool`
  - 获取当前镜头可复用资产池
- `POST /api/video-assets/upload`
  - 上传角色图、场景图、分镜图、首尾帧等垫图资产
- `POST /api/video-assets/{asset_id}/promote`
  - 提升为故事级/章节级默认资产
- `POST /api/video-assets/{asset_id}/redraw`
  - 基于上传图做 AI 标准化重绘

其中 `asset-pool` 应至少包含：

- 当前镜头资产
- 上一镜头可继承资产
- 当前场次共享资产
- 当前章节全局资产
- 当前故事全局资产

## 18. 开发改造优先级

### 第一优先级

1. 把右侧默认面板改成“当前镜头资产工作流”。
2. 增加镜头级资产聚合接口。
3. 把角色图、场景图、主分镜图、首尾帧串起来。

### 第二优先级

1. 增加镜头资产计划生成接口。
2. 视频接口升级为真正的资产束输入。
3. 视频提交前展示“将使用哪些资产”。

### 第三优先级

1. 增加镜头资产版本切换。
2. 增加上下镜头连续性引用。
3. 增加首尾帧和上一镜头的衔接检查。

## 19. 结论

你指出的问题是对的，当前视频模式的关键错误不是“功能缺几个按钮”，而是：

`资产管理没有嵌入镜头工作流，导致资产没有变成视频生成的主输入。`

后续必须改成：

1. 镜头是中心
2. 右侧是当前镜头资产工作台
3. 角色图、场景图、主分镜图、首尾帧先生成和确认
4. 资产必须能继承到下镜头、设为全局通用
5. 资产既支持用户上传垫图，也支持 AI 直接生成
6. 用户必须能手动选择资产图组成视频生成资产包
7. 视频最后基于这些资产束生成

只有这样，资产管理才不是摆设，而会真正决定视频质量和一致性。
