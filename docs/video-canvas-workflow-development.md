# 视频无限画布独立工作流开发文档

## 1. 文档目标

本文定义 StoryCanvas 的“视频无限画布”独立工作流的产品边界、技术设计、实施顺序和验收标准。目标是在不破坏既有视频生成能力的前提下，提供一个以节点图为核心的可视化编排工具：创作者可在无限画布上组织故事、剧本、分镜、素材、风格和生成任务，并将可执行的节点图提交到现有视频生成服务。

本文是开发与评审的共同依据。第 1 至 15 节保留设计边界与验收要求，第 16 节记录当前交付状态；接口、数据模型和状态机以第 13、14、16 节为准。任何实现若改变下文定义的独立性、权限、计费或数据保留规则，必须先更新本文并完成评审。

## 2. 产品范围

### 2.1 要解决的问题

- 让用户以可视化节点图表达视频创作过程，降低跨多个表单和页面切换的成本。
- 让剧本、场景、镜头、参考图和视频片段形成可追溯的数据链路。
- 支持从现有故事、剧本、分镜和媒体资产导入，而不复制或覆盖原始业务数据。
- 支持按节点或按整个图运行，并明确展示依赖、排队、失败、费用和可恢复状态。
- 让 Agent 在用户授权范围内建议或生成节点和连线，但不得绕过人工确认、权限和计费控制。

### 2.2 本期包含

- 独立的无限画布页面、画布列表和画布详情页。
- 节点图的保存、版本、导入、校验、运行、取消和结果回写。
- 文本、素材、风格、生成、合成、输出和注释等基础节点。
- 对既有故事/剧本/分镜/镜头/图片/视频资源的只读引用及显式同步。
- 与现有异步任务管理、配额、计费、图片 API、视频 API、ComfyUI 视频服务的集成适配层。
- 面向单画布的 Agent 辅助编排、审查与修复建议。

### 2.3 本期不包含

- 替换或删除现有“视频工作流”页面、API、数据库表和任务路径。
- 多人实时协同编辑、光标同步、评论流或冲突自动合并。
- 将任意第三方工作流格式无损导入并执行。
- 新建独立的支付体系、独立任务队列或绕过现有配额系统。
- 自动发布到外部社交平台、云盘或视频平台。
- 对版权、人物肖像、音乐授权作法律结论；系统仅提供声明、审计和拦截能力。

## 3. 两套独立工作流边界

### 3.1 既有视频工作流

既有工作流是面向故事、剧本、场景、镜头和视频生成的线性业务流程。其入口、路由、已有数据库实体、任务状态、前端状态持久化和 API 契约继续保持稳定。现有用户可不接触画布功能而完整使用原有能力。

### 3.2 新的视频无限画布工作流

新工作流以 `VideoCanvas` 为顶级聚合对象。画布中保存布局、节点配置、连线、引用快照、执行计划和运行记录；它可以调用既有服务，但不能直接篡改既有业务实体。画布生成的输出登记为既有 `VideoAsset`，可被资产管理和后续工作流显式选用；本期不实现反向覆盖列表分镜。

### 3.3 共享与隔离规则

| 领域 | 共享方式 | 禁止行为 |
| --- | --- | --- |
| 用户、故事、章节、剧本、镜头 | 通过稳定 ID 只读引用；导入时存快照 | 画布保存时隐式修改源实体 |
| 图片、视频资产 | 引用现有资产记录或创建新资产记录 | 复制大文件、覆盖源文件、删除其他流程资源 |
| 图片/视频生成服务 | 复用统一服务适配层和后台任务管理器 | 画布直接调用供应商 API 绕过审计 |
| 配额、订单、用量 | 复用 `FEATURE_CATALOG`、套餐和月度用量规则 | 使用画布专属扣费旁路 |
| Agent | 复用鉴权、模型配置、流式输出能力 | Agent 自动提交收费生成任务 |

### 3.4 发布和同步原则

画布对外写入必须是显式命令，分为“导入”“拉取更新”“发布结果”三类。每次命令生成一条同步记录，包含源、目标、字段映射、操作者、时间、前后摘要和结果。发生冲突时默认停止并要求用户选择，不以最后写入覆盖源数据。

## 4. 用户与核心流程

### 4.1 用户角色

- 创作者：创建、编辑、运行自己有权限的画布，管理私有资产。
- 协作者：后续扩展角色；本期不开放实时协作，但数据模型预留所有者与访问控制位。
- 管理员：查看受权限约束的运行审计、供应商错误和计费异常，不直接读取用户私有提示词全文，除非满足既有管理审计政策。

### 4.2 主流程

1. 用户从视频模块进入“无限画布”，新建空白画布或从故事/剧本/分镜创建。
2. 前端创建本地草稿并调用保存 API，得到画布及首个版本。
3. 用户拖入节点、配置端口、连线和画布分组；前端即时校验类型、方向、循环和必填字段。
4. 用户从资源库导入素材或从既有实体建立引用；系统记录引用版本和摘要。
5. 用户预检画布，后端构建执行计划，返回阻塞错误、警告、预计节点数和预计配额消耗。
6. 用户确认后运行全部或选定输出节点上游的子图；系统冻结本次运行的图快照。
7. 后台依拓扑顺序创建任务，复用统一任务管理器并将结果回写至本次运行的节点输出。
8. 用户检查结果，选择重跑单节点、替换输入、导出或显式发布到既有视频流程。

## 5. 画布 UI 设计

### 5.1 页面结构

- 画布列表页：搜索、按故事/状态/更新时间筛选、新建、复制、归档、最近运行状态。
- 画布编辑页：顶部命令栏、左侧节点库与资源库、中部无限画布、右侧检查器、底部运行与日志面板。
- 运行详情抽屉：展示冻结图版本、执行计划、每个节点的输入摘要、任务 ID、费用、日志和产物。
- 同步对话框：展示源与目标、字段映射、冲突项和用户需要确认的变更。

### 5.2 交互要求

- 画布支持平移、缩放、框选、对齐、复制粘贴、撤销重做、节点分组、最小化和搜索定位。
- 连线从输出端口拖至兼容输入端口；悬停时显示类型和不兼容原因。
- 节点宽高使用稳定约束，长文本在检查器中编辑，不因运行状态或错误文本改变节点尺寸。
- 执行状态使用颜色、图标和文字三重表达，不能只依赖颜色。
- 删除连线、删除节点、覆盖运行结果、发布到既有流程必须二次确认；删除节点前列出会受影响的下游节点。
- 自动保存采用节流和版本号并发控制；离开页面前提示未持久化的本地变更。

### 5.3 前端技术边界

建议采用 React 生态成熟的节点图组件库（例如 React Flow）实现画布交互，封装为画布领域组件，不将节点状态混入 `App.tsx` 的全局状态。画布编辑状态可使用模块级发布订阅 Store，持久化状态以服务端画布版本为准。引入新依赖前需评估 React 19、TypeScript 6 和现有 Vite 构建兼容性。

## 6. 节点、端口与图校验

### 6.1 节点类别

| 类别 | 节点 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 输入 | 文本、故事引用、剧本引用、分镜引用 | 配置或外部引用 | `text`、`screenplay`、`shot_list` |
| 资产 | 图片资产、视频资产、音频资产、角色资产 | 资产引用 | `image`、`video`、`audio`、`character` |
| 创作 | 场景拆解、镜头规划、提示词构建、连续性审查 | 文本、剧本、角色、风格 | `scene_list`、`shot_list`、`prompt`、`review` |
| 风格 | 风格预设、风格混合、负面提示词 | 风格或文本 | `style`、`prompt` |
| 生成 | 图像生成、图生视频、文生视频、配音生成 | 提示词、资产、参数 | `image`、`video`、`audio` |
| 后处理 | 镜头拼接、字幕、配乐、质量检查 | 视频、音频、文本 | `video`、`report` |
| 控制 | 条件分支、人工确认、注释、分组 | 任意受支持类型 | 透传或控制信号 |
| 输出 | 预览、导出、发布到视频工作流 | 视频、剧本、镜头或资产 | `published_asset`、`publish_receipt` |

### 6.2 端口协议

每个端口定义 `key`、显示名、方向（`input`/`output`）、数据类型、是否必填、是否多值、是否允许空值和架构版本。基础数据类型为：`text`、`json`、`story_ref`、`screenplay`、`scene_list`、`shot_list`、`prompt`、`style`、`character`、`image`、`image_list`、`video`、`video_list`、`audio`、`report`、`approval` 和 `error`。

端口兼容性由后端注册表定义，前端仅缓存并展示规则。允许显式转换节点，例如 `image -> image_list`；禁止前端用隐式数组包装绕过类型检查。

### 6.3 图约束

- 正式执行的图必须为有向无环图；控制节点也不得形成无限循环。
- 一个单值输入端口最多接一条有效边，多值端口按明确顺序接收多条边。
- 每个可运行输出节点的上游必填输入必须有值、连接或可解析默认值。
- 节点配置必须通过对应节点类型的 JSON Schema/Pydantic 校验。
- 不允许跨画布连线；跨画布复用使用“画布引用/导入”节点并冻结引用版本。
- 被禁用节点不参与执行计划，若其输出被依赖则预检失败。

## 7. 数据模型与版本策略

### 7.1 新增核心实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `video_canvases` | `id`、`owner_id`、`story_id`、`name`、`description`、`status`、`current_version`、`viewport`、时间戳 | 画布元数据与当前版本指针 |
| `video_canvas_versions` | `id`、`canvas_id`、`version_no`、`graph_json`、`source`、`created_by`、`change_summary` | 不可变的图快照，保存和运行均可追溯 |
| `video_canvas_runs` | `id`、`canvas_id`、`canvas_version_id`、`scope_json`、`status`、`requested_by`、`estimated_usage`、`actual_usage` | 一次执行请求及冻结范围 |
| `video_canvas_run_nodes` | `id`、`run_id`、`node_id`、`attempt`、`status`、`input_snapshot`、`output_snapshot`、`task_id`、错误字段 | 运行中的节点实例，关联既有后台任务 |
| `video_canvas_assets` | `id`、`canvas_id`、`source_type`、`source_id`、`storage_path`、`mime_type`、`checksum`、`metadata_json` | 画布资产索引，不持有重复大文件 |
| `video_canvas_sync_records` | `id`、`canvas_id`、`direction`、`source_ref`、`target_ref`、`mapping_json`、`before_json`、`after_json`、`status` | 显式导入、拉取、发布的审计记录 |
| `video_canvas_agent_sessions` | `id`、`canvas_id`、`user_id`、`messages_json`、`proposal_json`、`applied_at` | Agent 对话与提案记录 |

### 7.2 图 JSON 结构

`graph_json` 是版本化 JSON 文档，至少包含 `schema_version`、`nodes`、`edges`、`groups`、`viewport`、`metadata`。节点使用稳定 UUID，不以数组下标作为身份；边记录源节点/端口、目标节点/端口、排序和可选映射。敏感配置不得存入图 JSON，例如供应商密钥、用户认证令牌或完整支付信息。

### 7.3 版本与并发

- 编辑保存带 `expected_version`；服务端版本不一致时返回 `409` 与当前版本摘要。
- 每次用户主动保存创建新不可变版本，自动保存可合并为短时间窗口内的一次版本。
- 运行必须绑定具体 `canvas_version_id`，运行途中编辑画布不影响已提交的执行计划。
- 支持复制画布和从历史版本恢复为新版本，不允许原地修改历史快照。
- 资产引用在运行时冻结为资产 ID、校验和、URL/路径版本和必要元数据，保证结果可复现。

## 8. 导入、发布与第三方同步

### 8.1 内部导入

支持从故事、章节、视频剧本、场景、镜头、漫画图片、已生成视频导入。导入向导应允许选择“只引用”“复制为画布文本快照”“引用并创建转换节点”。默认只引用且保存展示摘要；当源数据已变化时，画布显示“引用已过期”，由用户主动拉取更新。

### 8.2 内部发布

输出节点可将经确认的剧本、镜头列表、图片或视频发布到既有视频工作流。发布 API 必须接收目标实体、字段白名单和目标版本；后端在一个事务中校验权限、写入目标、记录同步审计。若目标已变化，返回冲突详情，不自动覆盖。

### 8.3 第三方同步

本期不直接实现特定第三方平台的写入同步，但预留 `external_provider`、`external_resource_id`、`sync_cursor`、`last_synced_at` 和状态字段。后续适配器必须满足：

- 使用 OAuth/服务端凭据存储，不将凭据下发到浏览器或写入图 JSON。
- 支持幂等键、速率限制、重试上限、超时和可审计错误。
- 导入结果先进入画布资产或草稿节点，用户确认后才影响既有业务数据。
- 遵守供应商数据删除、版权和区域合规要求；连接失效时停止同步并通知用户。

## 9. 资产与风格管理

### 9.1 资产规则

- 统一复用既有静态资源路径和资产元数据，不改变 `manga_outputs`、`video_outputs` 的保留策略。
- 上传资产必须校验 MIME、文件大小、扩展名与内容签名；生成资产应保留来源节点、运行 ID、模型与参数摘要。
- 删除画布只能删除其数据库引用和画布私有的可回收资产标记，绝不删除仍被故事、既有视频工作流或其他画布引用的物理文件。
- 下载、预览和外部 URL 访问均按既有认证和资源授权规则执行。

### 9.2 风格规则

风格预设由名称、正向提示词、负面提示词、模型建议、视觉参数、缩略图资产引用和版本组成。风格混合节点只能组合用户有权使用的预设，需记录贡献比例和最终解析提示词。不同模型的参数差异由适配层转换，不允许节点直接拼装供应商私有字段。

## 10. 执行、任务与计费

### 10.1 执行计划

预检服务根据目标输出节点反向收集依赖，拓扑排序后生成不可变执行计划。计划列出将运行的节点、缓存命中、等待人工确认的节点、外部调用、预计时长和预计配额。预检结果签名或绑定图版本与输入摘要，正式提交时若内容变化必须重新预检。

### 10.2 任务编排

- 画布运行协调器只负责编排，具体生成仍通过 `task_manager.submit_task` 和既有服务提交。
- 节点进入 `queued`、`running`、`succeeded`、`failed`、`cancelled`、`skipped`、`awaiting_approval` 等状态。
- 上游失败时下游标记为 `skipped`，除非节点声明可处理 `error` 端口。
- 取消运行设置取消标记并向既有任务管理器请求取消；已完成资产保留，未完成任务遵循既有优雅取消语义。
- 单节点重试生成新的 `attempt`，不得覆盖先前输出与错误记录。

### 10.3 幂等、缓存与配额

每次提交使用 `idempotency_key`，由用户、图版本、目标范围和请求 nonce 组合，防止网络重试重复扣费。可缓存的纯转换节点按输入哈希、节点版本和参数哈希命中；调用生成模型的节点默认不跨用户复用结果。

计费预检使用现有 `FEATURE_CATALOG` 和套餐规则估算，提交前完成额度预留或等价的原子可用额度校验。实际消耗按已成功提交的可计费节点记录；供应商失败、取消和重试的扣费/返还必须遵守平台统一规则，并在运行详情可解释。

## 11. Agent 设计

### 11.1 能力边界

Agent 可读取用户有权访问的画布摘要、节点定义、端口约束、运行错误和可选的故事上下文，用于回答问题、推荐节点、生成草稿图、解释校验错误和提出修复补丁。Agent 输出必须是结构化提案（新增/更新/删除节点和边），不能直接写数据库或发起生成任务。

### 11.2 人工确认与审计

- 用户在画布预览变更后显式“应用提案”；应用操作创建新画布版本。
- Agent 不得读取 API Key、令牌、支付信息、其他用户私有内容或未授权资产。
- 可能产生费用的提案必须标记成本影响，应用后仍需经过常规预检与用户运行确认。
- 保存会话、模型、提示词模板版本、工具调用摘要和应用结果，以支持问题追踪；日志展示需脱敏。

## 12. 安全、权限与合规

- 所有画布、版本、运行、资产、同步和 Agent API 必须验证 JWT/API Token，并在服务端验证对象归属或授权范围。
- 后端不得信任前端传入的资产 URL、节点类型、预估费用、任务状态或供应商响应状态。
- 节点配置采用白名单 schema；提示词、文件名、外部 URL 和 JSON 输入需限制长度、结构深度与危险协议。
- 文件上传与第三方回调必须防止路径穿越、SSRF、任意文件读取、内容类型伪造和未验证重定向。
- 对图像/视频生成前的场景文本执行现有 `sanitize_scene_text()` 等安全策略；拒绝或替换应在节点运行记录中可追溯。
- 日志、同步记录和错误返回需脱敏密码、TOKEN、KEY、Authorization 等字段；生产审计不记录完整密钥。
- 删除采用软删除与延迟回收；涉及用户生成资源时严格遵守现有资源保护红线。

## 13. API 设计

所有画布接口位于 `/api/video-canvas/*`，不复用或改名既有 `/api/video/*` 路由。请求和响应模型定义在 `backend/schemas.py`，路由实现位于 `backend/routers/video_canvas.py`，运行时位于 `backend/services/video_canvas_runtime.py`，避免继续膨胀 `main.py`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/video-canvas/node-catalog` | 获取节点类型、端口和连线规则 |
| `POST` | `/api/video-canvas/canvases` | 新建空白画布 |
| `GET` | `/api/video-canvas/stories/{story_id}/canvases` | 查询当前作品的画布 |
| `GET` | `/api/video-canvas/stories/{story_id}/list-workflows` | 查询可显式导入的列表工作流 |
| `GET` | `/api/video-canvas/canvases/{canvas_id}` | 获取元数据、当前图版本、布局和最近运行 |
| `PATCH` | `/api/video-canvas/canvases/{canvas_id}` | 更新画布名称和描述 |
| `PUT` | `/api/video-canvas/canvases/{canvas_id}/graph` | 带乐观锁保存图并创建不可变版本 |
| `PUT` | `/api/video-canvas/canvases/{canvas_id}/layout` | 带乐观锁保存节点布局和视口 |
| `POST` | `/api/video-canvas/canvases/{canvas_id}/validate` | 校验图并返回诊断与拓扑顺序 |
| `POST` | `/api/video-canvas/canvases/{canvas_id}/imports/list-workflow` | 预览或合并导入列表分镜工作流 |
| `POST` | `/api/video-canvas/canvases/{canvas_id}/runs` | 冻结图版本并创建待确认运行计划 |
| `POST` | `/api/video-canvas/canvases/{canvas_id}/runs/{run_id}/confirm` | 用户确认后派发生成任务 |
| `POST` | `/api/video-canvas/canvases/{canvas_id}/runs/{run_id}/cancel` | 持久化取消并请求任务停止 |
| `GET` | `/api/video-canvas/canvases/{canvas_id}/runs/{run_id}` | 查询运行和节点状态 |

长任务状态可复用现有轮询模式；如增加 SSE，仅用于运行状态和 Agent 输出，并需支持断线重连游标、权限复核和明确结束事件。

## 14. 数据库迁移与兼容性

项目无 Alembic，新增表、索引、约束和枚举值应纳入 `backend/database.py` 的 `init_db()` / `_migrate()` 增量迁移流程。迁移必须可重复执行，并在 PostgreSQL 空库、已有生产库、旧版本前端三种情形验证。

- 先创建新表和非破坏性索引，再发布后端读写能力，最后发布前端入口。
- 所有外键、`owner_id`、`canvas_id`、`run_id`、`status`、更新时间和常用过滤列建立适当索引。
- `graph_json`、输入输出快照使用 JSONB；大型日志与媒体二进制不写入 JSONB。
- 不对现有视频表做破坏性字段修改，不删除或重命名既有路由和资源目录。
- 回滚策略以停用入口和保留新表数据为主；已启动的运行可由旧任务管理器收尾，不依赖删除数据库对象。

- 系统能阻止非法端口连接、循环图、必填输入缺失、无权限资源和不兼容节点配置，并返回可定位的错误。

- 发布操作需要用户确认，发生版本冲突时不覆盖目标；每次导入、拉取和发布均有审计记录。
- Agent 只能生成待确认提案，不能越权访问资产、提交收费任务或直接修改图。
- 所有新增迁移在空库与已有库可重复执行，后端测试、前端构建和核心端到端测试通过。

## 18. 风险与缓解措施

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 图结构与供应商参数快速膨胀 | 难维护、前后端不一致 | 用版本化节点注册表和适配层隔离供应商参数 |
| 异步任务中途失败 | 成本不透明、状态错乱 | 冻结运行快照、节点级状态机、幂等键与可审计重试 |
| 画布编辑并发 | 用户修改丢失 | 乐观锁、版本冲突提示、历史版本恢复 |
| 资产跨流程引用 | 误删用户生成资源 | 引用计数、软删除、物理删除延迟回收、资源保护回归测试 |
| 计费与实际供应商消耗不一致 | 账务争议 | 预估与实际分离记录、原子额度控制、异常对账告警 |
| Agent 误操作或提示词泄露 | 安全与信任风险 | 结构化提案、人工确认、最小权限、字段脱敏与审计 |
| 画布过大 | 浏览器卡顿、保存慢 | 节点数量上限、虚拟化、增量渲染、压缩快照和服务端大小限制 |
| 第三方同步不稳定 | 重复写入或数据冲突 | 适配器、幂等键、速率限制、同步游标和显式冲突处理 |
